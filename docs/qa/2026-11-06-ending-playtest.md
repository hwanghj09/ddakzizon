## 재현된 문제

### QA-01 · P2 · 학교로 간다는 버튼이 집으로 돌아간다

재현: 첫 귀가 → 신문지 접기 → 지우개 연습 완료 → **학교로 가기 →** 클릭.

실제: `home`, x=720의 집 연습 표적으로 돌아온다. 학교 앞까지 집 문·골목·광장·주민센터 앞을 다시 지나가야 한다. 문구가 약속하는 목적지와 동작이 다르다.

검토 방향: 실제로 학교로 이동시키거나, 걸어가도록 설계했다면 버튼을 ‘연습 마치기 / 집으로’로 바꾼다. 위치: `school.js:47`.

### QA-02 · P2 · 훈련 한도에서 지급되지 않는 +1을 보상으로 표시한다

재현: 훈련장에서 현재 성장 한도까지 훈련 → 선택 이야기의 과제 완료 → 결과 확인.

실제: 마을 `village_2`의 두 과제에서 XP 15→15, 시 대회 `city_0`의 두 과제에서 XP 30→30인데도 결과에 **+1 / 훈련**을 표시했다. 돈은 정상 지급됐다. 한도에 도달하면 증가하지 않는 규칙과 결과 문구가 맞지 않는다.

검토 방향: 실제 증가량을 표시하거나 ‘현재 훈련 한도 도달’을 안내한다. 위치: `journey-data.js`의 `complete()`는 XP를 한도로 제한하고, `journeys.js`의 `finish()`는 항상 +1을 표시한다.

### QA-03 · P3 · 아빠와의 아침 당번 약속이 승패와 반대로 끝난다

재현: 대륙 결승 전 선택 이야기 ‘아빠의 딱지’ → ‘아빠와 한 판’ 승리.

경기 전 아빠는 ‘이긴 사람이 내일 아침 차리기다.’라고 약속한다. 실제로 주인공이 이긴 뒤에는 아빠가 ‘졌다. 내일 아침은 내가 할게.’라고 말한다. 경기 결과와 약속의 조건이 반대다. ‘지는 사람이’로 고치려는 장면인지 확인이 필요하다. 위치: `journey-data.js`의 `continent_2` 두 번째 과제.

### QA-04 · P2 · ‘그날의 나’가 주인공 대신 민수 모습으로 나온다

재현: 행성 결승 전 ‘처음 그 운동장’ → 두 번째 과제 ‘그날의 나’.

대사는 과거의 주인공 홀로그램이라고 설명하지만, 상대는 초록 옷·갈색 머리의 민수 스프라이트다. 첫날부터 주인공은 파란 모자·붉은 옷을 입는다. 데이터의 `kind:'rival'`이 `art.js:5`에서 `minsu`로 연결되어 발생한다. 이 상대에만 주인공 `sprite`를 명시하는 방향을 검토한다. 위치: `journey-data.js`의 `planet_2`, `world-scenes.js:53`.

### QA-05 · P2 · 작은 PC 창에서 경기 준비 버튼의 키보드 포커스가 화면 밖에 남는다

재현: PC 창 **1024×600** → 도 대회 접수 → 1회전 자유 경기의 준비 화면 → 방향키 ↓.

초기 선택인 ‘경기 시작’부터 내용 영역 아래에 가려져 있다. ↓로 ‘딱지 바꾸기 → 강화·훈련하러 가기 → 뒤로’를 선택해도 내용 스크롤은 0으로 유지되어 포커스가 보이지 않는다. 실제 ‘강화·훈련하러 가기’의 y=642~682에 비해 표시 영역은 y=139~467이었다. Shift+Tab을 사용하자 스크롤이 274로 바뀌고 버튼이 보였다.

키보드 선택 자체는 작동하지만 무엇을 선택했는지 볼 수 없다. 초기 포커스와 방향키 이동 시 선택한 버튼을 스크롤 영역 안으로 가져와야 한다. 위치: `tournament.js:38`, `village.js:92`의 `focus({preventScroll:true})`.

## 앞선 요청과 최신 전체 이야기의 차이

아래는 현재 기획 문서의 일부 설정과는 일치한다. 실행 오류로 단정하지 않고, 사용자가 앞서 요청한 흐름과 다른 점으로 구분한다.

1. **아쉽게 지는 접전이 아니다.** 첫 경기 내구도는 나 25 : 민수 100. 실제 첫 GOOD 타격으로 12 피해를 준 뒤, 내 0 : 상대 88로 강제 패배했다. 최신 코드는 한 번의 공격 뒤 강제 패배하도록 되어 있다 (`game-battle.js:4`, `game-battle.js:19`).
2. **패배 직후 집으로 페이드 이동하지 않는다.** 패배 대사와 카드 뒤 운동장 x=520으로 복귀한다. 집까지 여러 구역을 걸어가야 한다 (`game-battle.js:21`).
3. **첫 귀가 때 아빠에게 강화 방법을 배우지 않는다.** 접기 두 번과 지우개 연습을 하고, 공격 20·내구 100·압축 +0인 채 학교로 돌아간다. 아빠의 선택 이야기는 마을 1승 뒤 수첩에 열리며, 압축기 안내도 마을 1승 뒤다.
4. **캐릭터 원본은 32×32가 아니라 64×64다.** 최신 커밋이 의도적으로 64×64 캐릭터를 적용했고, 주인공·아빠 PNG 실측도 64×64다. 딱지 이미지는 32×32다. 앞서 정한 ‘배경 제외 32×32’ 기준을 계속 적용할지는 기획 확인 대상이다. 화면 오류로 분류하지 않는다.

## 연출·안내 검토

- 접기 순서를 모두 맞춰도 첫 접기는 무조건 비뚤어지고 같은 네 번 입력을 반복한다. 첫 연습 PERFECT도 양말을 맞힌 것으로 연출된다. 최신 스토리 문서에 있는 의도된 개그지만, 입력 실패인지 각본인지 구분이 약하다.
- **성적과 다른 고정 대사:** 마을 ‘같이 놀 사람’ 첫 과제는 PERFECT 5회였는데 민수가 ‘너도 빗맞히네?’라고 말한다. 도 대회 ‘다섯 번의 호흡’도 PERFECT 5회인데 주인공이 ‘완벽한 다섯 번은 아니었네.’라고 말한다. 모두 성공 처리되므로 보상 버그는 아니며, 실제 판정에 맞는 반응 또는 성적에 중립적인 대사가 필요하다 (`journey-data.js`).
- **내구도와 패배 원인의 안내:** 전국 준결승에서 내 내구 250/310, 상대 87/320인 상태로 패배했고 다음 시도도 내 230/310에서 졌다. 내구가 남아도 뒤집히면 진다는 확률 규칙에 맞는 결과다. 다만 결과 패널은 ‘가한 피해 / 완벽’만 보여 주어, HP가 크게 남은 패배의 이유를 복기하기 어렵다. ‘상대 정밀 타격으로 뒤집힘’처럼 종료 원인을 남기는 개선을 검토할 수 있다. 규칙 오류로 분류하지 않는다.
- **‘빗나감’의 의미:** 엔딩 후 친선전에서 실제 BAD 판정을 냈을 때 상대 내구가 420→390으로 줄고 피해 30이 집계됐다. `rules.js`에서 BAD도 0.6배 피해를 주는 의도된 규칙이다. ‘약한 타격’ 같은 이름 또는 설명이 더 정확하다.
- **진행 이후 조사 문구:** 아빠와의 이야기와 실제 대결을 모두 마친 엔딩 후에도 가족사진은 ‘왜 지금은 안 치실까?’라고 말한다. 사진·벤치 등 초기 조사 문구의 진행 단계별 갱신을 검토할 만하다. 가족사진은 `ending=true`, 아빠 이야기 `continent_2=2` 상태에서 다시 조사해 확인했다.
- PC 타이틀은 키보드·마우스 전용을 명시하지만 탐색 화면에는 가상 좌우·상호작용 버튼이 항상 나온다. `AGENTS.md`의 터치 이동 버튼 미추가 기준과 불일치한다. `index.html:8`, `game-input.js:14`, `menus.js`의 조작키 안내 참조.
